# Atoms Demo 实现说明

> 本文侧重设计取舍与完成度。完整的实现过程、系统架构、数据模型、接口规格与时序图见
> [架构与实现过程](架构与实现过程.md)；运行与部署步骤见 [README](../README.md)。

## 整体方案

```
浏览器
  ├─ /                 落地页：价值说明 + 一句话输入
  ├─ /login            昵称即登录
  ├─ /app              工作台：项目列表 + 新建
  ├─ /p/[id]           工作区：赛马进度 / 方案切换 / iframe 预览 / 迭代
  └─ /s/[id]           公开分享页（只读预览）

Next.js Route Handlers
  ├─ POST /api/projects/[id]/runs     SSE：2-3 路并行生成 → 评分 → 选中最佳
  ├─ POST /api/projects/[id]/iterate  基于当前 HTML 生成新版本
  ├─ POST /api/projects/[id]/select   手动选择方案（写入版本快照）
  └─ GET  /api/projects/[id]/export   导出单文件 HTML

PostgreSQL（Drizzle ORM）
  users / projects / runs / variants / versions
```

数据模型刻意保持扁平：一次赛马是一行 `run`，每路产物是一行 `variant`，每一次迭代或手动选择是一行 `version`。
这样「历史版本」「方案对比」「回看旧结果」都不需要额外状态。

## 关键取舍

### 1. 生成物是单文件 HTML，而不是 React 工程

- **为什么**：要求「生成的应用以可视化网页形式展示」且「真实交互」。单文件 HTML 可以塞进
  `iframe srcDoc` 直接运行，零构建、零依赖安装；导出的 `.html` 双击也能打开，满足自检法。
- **代价**：生成物不能用 npm 生态、不能是多文件工程。
- **为什么不选 React 工程**：需要在服务端安装依赖、起 dev server 或做在线构建，48 小时内不稳定，
  且部署环境（Serverless）不适合长驻构建进程。复杂度与收益不成正比，主动放弃。

### 2. 赛马模式选 2-3 路，而不是 5 路

- **为什么**：三路分别对应「极简 / 功能完整 / 视觉优先」，差异足够明显，演示时一眼能看出区别；
  同时把并发和 token 成本控制在可接受范围。
- **实现**：`Promise.allSettled` 语义的逐路任务，任何一路失败只影响自己；SSE 在每路完成时立即推送，
  不阻塞其它路。全部结束后调用评审模型打分，失败则降级为规则评分（控件数量、交互绑定、持久化、
  响应式、需求关键词命中），保证分数一定存在。

### 3. 用 SSE 而不是 WebSocket

赛马是单向、一次性的长任务，SSE 足够；Route Handler 原生返回 `ReadableStream`，无需额外网关，
Vercel/Zeabur 都能直接跑。事件协议只有 `run_start / variant_done / variant_failed / judge_start /
judge_done / run_done / run_failed` 七种，前端按事件增量更新，刷新后还能从数据库恢复完整状态。

### 4. PostgreSQL，而不是 SQLite

最初方案是 SQLite + 持久化 Volume，但目标部署平台是 Vercel（Serverless 无持久磁盘）。
Postgres 在本地用 Docker、线上用 Neon，**同一套 Drizzle 代码和迁移**，不需要为环境写两套数据层。
连接参数使用 `prepare: false`，兼容 Neon 的连接池。

### 5. 登录只做昵称，不做密码体系

题目要求覆盖「初始化 / 注册」等基本流程，但演示场景不需要完整的账号体系。昵称即身份，
服务端用 HMAC 签名写入 httpOnly Cookie。少写一套密码找回/邮箱验证，把时间留给闭环和稳定性。

### 6. 演示模式是一等公民

- 没有 API Key 时自动进入演示模式：三套内置应用（看板 / 房贷计算器 / 个人主页）按关键词匹配，
  三种人格用不同主题和功能深度渲染，仍然完整走赛马、评分、迭代、分享、导出。
- 真实模型生成失败、HTML 校验失败、评审失败都有降级路径。
- `/api/health` 暴露 `mockMode`，演示前一眼确认当前状态。
- 这样「能不能演示」不取决于额度、网络或 Key 是否可用。

### 7. iframe 安全：不加 `allow-same-origin`，额外补 storage shim

- 生成代码属于不可信内容。沙箱中不加 `allow-same-origin`，它就处于不透明源，
  读不到宿主的 Cookie、localStorage，也无法冒用会话调用业务接口。
- 副作用是浏览器在该源下禁用 `localStorage`，而生成的应用普遍依赖它。预览前注入一段极小的
  内存级 shim（仅在原生访问抛错时生效），让示例的增删改查照常工作；导出为独立文件后恢复原生存储。
- 这是一个明确的工程折中：**预览可用 + 宿主安全**，代价是预览内的数据不跨刷新持久化。

## 完成度

已完成并验证（本地真实浏览器 E2E，非仅接口测试）：

- 昵称登录、未登录访问工作台自动重定向
- 新建项目 → 三路并行生成 → 实时进度 → 评分 → 自动选中最佳
- iframe 内真实交互（新增任务、状态切换、删除）
- 刷新页面后项目、方案、版本、分数仍在
- 对话式迭代生成 v2，旧版本可回看
- 分享链接免登录可访问、可交互
- 导出单文件 HTML
- 演示模式下全流程可跑通
- `npm run build`、`tsc --noEmit`、`eslint` 均通过

未做（主动取舍）：

- 邮箱/密码、找回密码、OAuth
- 多智能体编排框架、工具调用
- 团队协作、实时多人编辑
- 任务队列 / 后台 worker（生成直接跑在请求内，靠 `maxDuration = 300` 兜底）
- 速率限制、内容审核、生成物 CDN 缓存
- 移动端原生体验（网页已做响应式，未单独适配）

## 如果继续投入，按这个优先级

1. **生成质量**：把「需求 → 结构化规格 → 代码」拆成两步，减少一次生成失败率；
   给模型附上设计系统与组件样例，提升首次生成的可交付度。
2. **迭代体验**：支持局部修改（选中元素后改），而不是整页重写；迭代也走多路对比。
3. **任务化**：把生成放入队列，支持关闭页面后继续跑、断线重连、失败自动重试。
4. **可观测性**：记录每路的耗时、token、失败原因，做一张简单的质量面板。
5. **安全**：生成物来源标记、速率限制、公开分享页的开关与过期时间。

## 演示脚本（3 分钟）

1. 首页输入「我要一个带优先级、截止日和拖拽排序的项目看板」，点开始。
2. 工作区展示三路智能体并行进度，逐路完成后出现分数；说明评委模型择优。
3. 在预览区直接新增任务、拖动状态，证明「生成物是真能跑的」。
4. 刷新页面，说明数据在 Postgres，版本和分数都还在。
5. 输入「把主色调换成蓝色」，生成 v2，左侧版本列表保留 v1。
6. 点分享复制链接，用无痕窗口打开，证明免登录可访问。
7. 打开 `/api/health` 或说明断网/无 Key 时的演示模式兜底。
