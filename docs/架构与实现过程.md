## 1. 需求到验收

### 1.1 最小闭环

题目要求的是「AI 驱动生成应用并可视化运行」，不是「用 AI 做一个业务应用」。据此把验收拆成四步：

```text
① 用户输入一句需求
      ↓
② 一个或多个智能体处理，生成代码 / 应用
      ↓
③ 页面上直接渲染出可运行的应用（iframe 预览）
      ↓
④ 生成结果被持久化（刷新 / 重开浏览器仍在）
```

四步缺一不可。延展能力只选一个做深：**赛马模式（多路并行生成 + 评分择优）**，
它最能体现对 Atoms 产品形态的理解，也最容易在演示中形成记忆点。

### 1.2 验收矩阵

| 验收项 | 实现位置 | 验证方式 |
| --- | --- | --- |
| 输入一句话生成应用 | `/p/[id]` + `POST /api/projects/[id]/runs` | E2E |
| 智能体真实调用模型 | `src/lib/llm.ts` + `src/lib/prompts.ts` | 真实 Key 待验证；mock 路径已验 |
| 页面内直接运行 | `iframe srcDoc` + `src/lib/preview.ts` | E2E：iframe 内新增任务 |
| 真实交互 | 生成物含按钮/输入/状态变化；宿主有赛马进度、版本切换、手动选择 | E2E |
| 数据持久化 | PostgreSQL + Drizzle：users / projects / runs / variants / versions | E2E：刷新后版本仍在 |
| 基本流程 | 昵称登录 → 工作台 → 新建 → 生成 → 预览 → 迭代 | E2E |
| 延展能力 | 赛马模式、对话式迭代、版本历史、分享、导出 | E2E |
| 无 Key 可演示 | 自动 mock + 失败自动降级 | 手工 + SSE 实测 |
| 可分享 | `/s/[id]` 免登录只读预览 | E2E |

## 2. 实现过程

### 2.1 阶段一：环境与约束勘察

动手前的三个事实决定了后续选型：

1. **部署平台不能拍脑袋选**。从本机实测：`render.com` 12 秒超时不可达；Vercel、Railway、Zeabur 可访问；
   `registry.npmjs.org` 可达且 npm 已配置国内镜像。Render 因此被排除。
2. **本地具备完整工具链**：Node 22.20、npm 10.9、Docker 29.9（可用于本地 Postgres）、Vercel CLI 65。
3. **交付风险高于功能风险**。按避坑文档，链接活着、仓库公开、数据持久化是一票否决项。
   因此方案从一开始就按「可部署」倒推：Serverless 无持久磁盘 → 不用 SQLite → 用 Postgres。

### 2.2 阶段二：选题与闭环定稿

放弃「做一个看板/计算器应用」，改为**通用的应用生成器**：内置看板、房贷计算器、个人主页三个示例，
由模型自由生成。这样既符合「生成器」的题意，又避免被判定为「你用 AI 做了个业务应用」。

最小闭环确定为：

```text
一句话 → 2-3 路并行生成 → 评分择优 → iframe 运行 → 落库 → 迭代
```

延展能力只保留赛马模式；迭代作为赛马的自然延伸顺带实现；注册、团队协作、多智能体编排全部砍掉。

### 2.3 阶段三：骨架与数据层

1. `git init` + `create-next-app` 生成 Next.js 16（App Router、TS、Tailwind 4、src 目录、Turbopack）。
2. 安装 `drizzle-orm`、`postgres`、`zod`、`clsx`、`lucide-react`、`drizzle-kit`。
3. 用 `docker compose` 起 PostgreSQL 16（宿主端口 5433，避免与本机 5432 冲突）。
4. 建 `src/db/schema.ts`、`src/db/index.ts`，用 `drizzle-kit push` 建表，并生成 SQL 迁移 `drizzle/0000_*.sql`。
5. 实现 HMAC 签名 Cookie 会话（`src/lib/session.ts`）和昵称登录。

数据层刻意保持扁平：一次赛马一行 `run`，一路产物一行 `variant`，一次迭代或手动选择一行 `version`。
这样历史、对比、回看都不需要额外状态。

### 2.4 阶段四：生成层

生成层按「可替换、可降级」设计：

- `src/lib/personas.ts`：三路智能体人设（极简派 / 功能派 / 视觉派），各自带系统提示补充。
- `src/lib/prompts.ts`：生成系统规则（单文件 HTML、内联样式脚本、必须可交互、localStorage 持久化、响应式）
  与评审提示词（四个维度、只输出 JSON）。
- `src/lib/llm.ts`：原生 `fetch` 调 OpenAI Chat Completions 兼容接口；`AbortController` 控制超时；
  抽取 HTML、校验完整性；评审失败抛错由上层降级。
- `src/lib/html.ts`：从模型输出中剥离 Markdown 代码块、截取完整文档、校验 `<html>/<body>`。
- `src/lib/score.ts`：规则评分兜底（控件、事件、持久化、响应式、需求关键词等信号）。
- `src/lib/mock.ts`：三套内置应用 × 三种风格，用于无 Key 演示和失败兜底。

### 2.5 阶段五：API

按「一次赛马就是一次流式请求」实现：

- `POST /api/projects/[id]/runs`：SSE，逐路推送生成结果，全部完成后评审、选优、写版本。
- `POST /api/projects/[id]/iterate`：基于用户当前查看的版本/方案生成新版本。
- `POST /api/projects/[id]/select`：手动选择方案，写入版本快照。
- `GET /api/projects/[id]/export`：导出单文件 HTML。
- `GET /api/health`：暴露当前是否 mock，方便演示前自检。

接口统一校验登录与项目归属，错误统一返回 `{ error }` 与状态码。

### 2.6 阶段六：前端

页面与组件：

- `/` 落地页：价值说明 + 一句话输入 + 赛马说明 + 能力矩阵。
- `/login`：昵称登录，支持安全的 `next` 回跳。
- `/app`：工作台，项目列表、聚合最高分、新建应用。
- `/p/[id]`：工作区，左侧赛马进度 / 版本时间线 / 迭代输入，右侧 iframe 预览 / 代码视图。
- `/s/[id]`：公开分享页，免登录只读预览。

视觉上使用深色底 + 紫色主色 + 玻璃感面板，全部 Tailwind 4 + 少量自定义 CSS 组件类，
不引入组件库，保证构建简单、体积可控。

### 2.7 阶段七：真实浏览器验证

接口能返回 200 不代表闭环成立，因此用本机 Chrome + `playwright-core` 写了端到端测试（`scripts/e2e.mjs`）：

```text
落地页 → 登录 → 新建项目 → 赛马完成 → iframe 可交互（新增任务）
→ 刷新后版本仍在 → 迭代 v2 → 重新赛马 v3 → 分享页可预览 → 未登录重定向
```

最终结果 13/13 通过，浏览器无运行时错误。

### 2.8 阶段八：稳定性与兜底

- 单路失败不影响其它路（每路 try/catch + `variant_failed` 事件）。
- 评审失败 → 规则评分。
- **全部路失败 → 自动切换内置示例继续演示**，通过 `fallback` 事件告知前端。
- 模型输出缺少完整 HTML → 该路失败，而不是把半截代码塞进 iframe。
- 迭代总是基于用户当前查看的版本，避免「看到的 A、改的是 B」。

### 2.9 问题与修复记录

| 问题 | 现象 | 根因 | 处理 |
| --- | --- | --- | --- |
| Next 16 配置冲突 | 构建报 `Route segment config "runtime" is not compatible with nextConfig.cacheComponents` | create-next-app 默认开启 `cacheComponents`，与 Route Segment Config 冲突 | 关闭 `cacheComponents` / `partialPrefetching`，移除各 route 的 `runtime` 配置，保留显式 `dynamic = 'force-dynamic'` |
| 沙箱内 localStorage 不可用 | 生成应用在 iframe 内点击报 `SecurityError` | 沙箱未加 `allow-same-origin`，属于不透明源，浏览器禁用存储 | 预览前注入内存级 localStorage/sessionStorage shim；导出文件使用原生存储 |
| 预览 iframe 被重置 | 赛马完成瞬间 iframe 重新加载，交互状态丢失 | `key` 绑定 activeVariant/activeVersion，二者切换导致重挂载 | 去掉 `key`，仅让 `srcDoc` 变化触发必要的重载 |
| 重新赛马版本号重复 | 多次赛马都叫 `v1 · 最佳方案` | 标题写死 | 生成前统计现有版本数，标题使用 `v{n} · 最佳方案` |
| 迭代基准错位 | 选中旧方案后继续修改，改的是最新版本 | 服务端只取 `pickActiveHtml` | 迭代请求携带 `baseVersionId` / `baseVariantId`，服务端校验归属后以其 HTML 为基准 |
| 贪心加载 pending prompt 触发 lint | React 报「effect 内同步 setState」 | 首屏读取 sessionStorage 后立即 setState | 改为 setTimeout 0 异步写入并在卸载时清理 |
| Render 不可达 | curl 12s 超时 | 本机网络访问 Render 受限 | 部署方案改为 Vercel + Neon，保留 Zeabur/Railway 备选 |

### 2.10 阶段九：文档与交付准备

补齐 README、实现说明、架构文档；生成 SQL 迁移；配置 `.gitignore`（`.env*`、node_modules、测试产物）；
检查仓库无 `sk-` 等密钥；整理本地运行与 Vercel + Neon 部署步骤。

### 2.11 开发方式与协作过程

本次实现以 **Claude Code** 作为主要结对工具，配合本机 Chrome（Playwright 驱动）、Docker 与命令行完成。
整个协作过程遵循「先定验收、再写代码、每步可验证」：

1. **先读题再动手**：从 `docs/目标.md` 与 `docs/避坑.md` 提炼出四步闭环、三条铁律与一票否决项，
   把它们转成验收矩阵，而不是直接开始写页面。
2. **先勘察再选型**：实测部署平台可达性、确认 Node/Docker/Vercel CLI 可用，再决定 Postgres 与 Vercel。
3. **AI 生成骨架，人做关键决策**：脚手架、数据层、API、UI 由 AI 起草；
   选题、延展能力、砍掉哪些功能、部署平台由人拍板。
4. **每步设门禁**：每次改动后跑 `tsc --noEmit`、`eslint`、`next build`，避免错误累积。
5. **用真实浏览器验收**：不满足于接口 200，编写 E2E 覆盖 iframe 内点击、刷新持久化、分享页与鉴权重定向。
6. **专项验证失败路径**：主动构造不可达模型端点，验证「三路全失败 → 自动切内置示例」确实生效。
7. **版本差异以本地文档为准**：Next.js 16 与训练数据存在差异（异步 `params`/`cookies`、Turbopack 默认、
   `cacheComponents`），先读 `node_modules/next/dist/docs/` 再写代码。
8. **安全边界主动检查**：生成代码视为不可信，iframe 不加 `allow-same-origin`；
   `.env*` 不入库；提交前扫描密钥。

AI 产出并非直接采信：构建错误、iframe 存储限制、预览重挂载、版本号重复等问题，
都是在「运行 → 观察 → 定位 → 修复 → 回归」的循环中暴露并解决的（见 2.9）。

## 3. 系统架构

### 3.1 运行时总览

```text
┌──────────────────────────────┐
│ Browser                      │
│  React 19 客户端组件          │
│  - 表单 / 赛马进度 / 版本列表 │
│  - iframe(sandbox) 运行生成物 │
└──────────────┬───────────────┘
               │ HTTP + SSE（fetch + ReadableStream）
┌──────────────▼───────────────────────────────┐
│ Next.js 16（App Router，Node runtime）        │
│                                              │
│  Server Components / Pages                   │
│    /  /login  /app  /p/[id]  /s/[id]         │
│                                              │
│  Route Handlers                              │
│    auth / projects / runs(SSE) / iterate     │
│    select / export / health                  │
│                                              │
│  Domain Lib                                  │
│    llm / prompts / personas / mock           │
│    score / html / preview / projects         │
│    session / auth / serialize                │
└───────┬───────────────────────┬──────────────┘
        │ SQL（postgres-js）     │ HTTPS（OpenAI 兼容）
┌───────▼──────────────┐  ┌─────▼────────────────────┐
│ PostgreSQL           │  │ LLM Provider             │
│ 本地 Docker / Neon   │  │ DeepSeek / 通义 / 其他    │
└──────────────────────┘  └──────────────────────────┘
```

要点：

- 没有独立后端服务，Next.js Route Handler 同时承担 API 与流式输出。
- 没有任务队列，赛马任务随请求生命周期执行，靠 `maxDuration = 300` 兜底。
- 生成物不经过构建系统，直接作为 HTML 字符串进入 iframe 与数据库。

### 3.2 代码分层

```text
src/
├── app/           路由与页面（服务端组件为主）
│   ├── api/       Route Handlers（HTTP 边界）
│   ├── page.tsx   落地页
│   ├── login/     登录页
│   ├── app/       工作台
│   ├── p/[id]/    项目工作区
│   └── s/[id]/    公开分享页
├── components/    客户端交互组件
├── lib/           领域逻辑（无框架耦合，除 Next 请求 API）
└── db/            Drizzle schema 与连接
```

依赖方向：`app → components / lib → db`。`lib` 内部不反向依赖页面，保证可测试与可替换。

### 3.3 部署拓扑

```text
GitHub（public）
      │ push
      ▼
Vercel（Next.js build + serverless functions）
      │ DATABASE_URL（pooled，sslmode=require）
      ▼
Neon PostgreSQL
      │
Vercel ──HTTPS──▶ LLM Provider
```

- 为什么不是 SQLite + Volume：Vercel Serverless 无持久磁盘。
- 为什么不是 Render：本机实测不可达。
- 备选：Zeabur / Railway（支持持久磁盘与常驻进程），代码无需改动，只需换环境变量。

### 3.4 技术选型

| 领域 | 选择 | 理由 |
| --- | --- | --- |
| 框架 | Next.js 16 App Router | 页面与 API 同仓同进程；Route Handler 原生支持流式 Response |
| UI | React 19 + Tailwind 4 | 无组件库依赖，48 小时内可控 |
| 语言 | TypeScript strict | 数据模型与 API 契约清晰，减少联调错误 |
| ORM | Drizzle + postgres-js | 类型安全、迁移可审查、Serverless 连接参数可控 |
| 数据库 | PostgreSQL | 本地 Docker 与线上 Neon 同构 |
| 模型 | OpenAI Chat Completions 兼容协议 | 不绑定厂商，换模型只改环境变量 |
| 流式 | SSE | 单向、一次性长任务，部署简单 |
| 测试 | playwright-core + 本机 Chrome | 不下载浏览器，真实渲染与 iframe 交互可验证 |

## 4. 数据模型

### 4.1 ER 关系

```text
users (1)
  │ user_id
  ▼
projects (n)
  ├── selected_variant_id ──────────────┐（逻辑引用，无外键）
  │                                     │
  ├── project_id                        │
  ▼                                     │
runs (n) ── run_id ──▶ variants (n) ◀───┘
  │                       ▲
  │ project_id            │ variant_id（逻辑引用）
  ▼                       │
versions (n) ─── parent_version_id ──▶ versions（自引用版本链）
```

### 4.2 表定义

#### users

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | uuid | PK，默认随机 | 用户 id |
| nickname | text | NOT NULL，UNIQUE | 登录标识，同名即同一用户 |
| created_at | timestamptz | NOT NULL，默认 now() | 创建时间 |

#### projects

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | uuid | PK | 项目 id，同时用作分享链接 |
| user_id | uuid | FK → users.id，级联删除 | 归属 |
| title | text | NOT NULL | 由需求首句派生，可后续更新 |
| prompt | text | NOT NULL | 原始需求 |
| selected_variant_id | uuid | 可空 | 当前选中的方案（逻辑引用） |
| created_at / updated_at | timestamptz | NOT NULL | 排序依据 |

#### runs

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | uuid | PK | 一次赛马 |
| project_id | uuid | FK → projects.id，级联删除 | 归属 |
| prompt | text | NOT NULL | 本次使用的需求 |
| status | text | 默认 `running` | `running` / `done` / `failed` |
| source | text | 默认 `llm` | `llm` / `mock`（含失败降级后的 mock） |
| error | text | 可空 | 失败原因 |
| created_at / completed_at | timestamptz | | 时序 |

#### variants

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | uuid | PK | 单个方案 |
| run_id | uuid | FK → runs.id，级联删除 | 所属赛马 |
| project_id | uuid | FK → projects.id，级联删除 | 冗余便于按项目查询 |
| idx | int | NOT NULL | 赛道序号 0..n |
| persona | text | NOT NULL | `minimal` / `feature` / `visual` |
| html | text | NOT NULL | 生成物全文 |
| score | int | 可空 | 评审分，生成完成后回填 |
| reasoning | text | 可空 | 评审点评 |
| latency_ms | int | 可空 | 该路耗时 |
| tokens | int | 可空 | token 用量（mock 为空） |
| created_at | timestamptz | NOT NULL | |

#### versions

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | uuid | PK | 版本快照 |
| project_id | uuid | FK → projects.id，级联删除 | 归属 |
| variant_id | uuid | 可空 | 来自某个方案时记录来源 |
| parent_version_id | uuid | 可空 | 版本链 |
| prompt | text | NOT NULL | 产生该版本的指令 / 需求 |
| html | text | NOT NULL | 快照内容 |
| title | text | 可空 | 展示名，如 `v2 · 把主色换成蓝色` |
| created_at | timestamptz | NOT NULL | |

### 4.3 生命周期

```text
创建项目
  └─ 赛马 run(running)
       ├─ variant × N 逐路写入（score 为空）
       ├─ 评审：回填 score / reasoning
       ├─ 选中最高分 → projects.selected_variant_id
       └─ 写入 versions：v1 · 最佳方案，run(done)

对话式迭代
  └─ 以当前查看的版本/方案为 base → 生成 HTML → 写入 versions(vN)，parent 指向 base

手动选择方案
  └─ 更新 selected_variant_id
       └─ 若最新版本不是该方案 → 写入一条版本快照

重新赛马
  └─ 新 run + 新 variants + v(n+1) · 最佳方案
```

### 4.4 设计说明

- **方案与版本分离**：方案是「赛马的产物」，版本是「用户最终看到的时间线」。
  手动选择或迭代都会产生版本，预览永远取「最新版本 > 选中方案 > 最高分方案」。
- **selected_variant_id / variant_id / parent_version_id 不加外键**：避免删除链路复杂化；
  读取时均校验归属，孤立引用只会退化为「找不到」，不会破坏数据。
- **HTML 明文入库**：便于导出、分享与重放；当前没有压缩与大小上限，属于已知限制。
- **没有额外索引**：数据量小；上线前应为 `variants.project_id`、`runs.project_id`、`versions.project_id` 补索引。

## 5. 接口规格

### 5.1 鉴权与会话

- 登录：`POST /api/auth/login`，只接受 `nickname`（1-20 字符）。
- 会话：HMAC-SHA256 签名 Cookie，名 `atoms_session`，值 `userId.signature`。
- 属性：`httpOnly`、`sameSite=lax`、生产环境 `secure`、30 天过期。
- 校验：`timingSafeEqual` 比较签名；无效或缺失即视为未登录。
- 服务端页面：未登录访问 `/app`、`/p/[id]` 会 307 到 `/login?next=...`。
- API：未登录返回 401 `{ error: '请先登录' }`。

### 5.2 REST API 一览

| 方法 | 路径 | 鉴权 | 请求体 | 成功响应 |
| --- | --- | --- | --- | --- |
| POST | `/api/auth/login` | 否 | `{ nickname }` | `{ user: { id, nickname } }` |
| POST | `/api/auth/logout` | 否 | — | `{ ok: true }` |
| GET | `/api/projects` | 是 | — | `{ projects: [{ id,title,prompt,variantCount,bestScore,createdAt,updatedAt }] }` |
| POST | `/api/projects` | 是 | `{ prompt }` | 201 `{ project }` |
| GET | `/api/projects/[id]` | 是 | — | `{ project, variants, versions, mockMode }` |
| DELETE | `/api/projects/[id]` | 是 | — | `{ ok: true }` |
| POST | `/api/projects/[id]/runs` | 是 | `{ prompt?, lanes? }` | SSE 流（见 5.3） |
| POST | `/api/projects/[id]/iterate` | 是 | `{ instruction, baseVersionId?, baseVariantId? }` | `{ version, source }` |
| POST | `/api/projects/[id]/select` | 是 | `{ variantId }` | `{ version, created }` |
| GET | `/api/projects/[id]/export` | 是 | — | `text/html` 附件 |
| GET | `/api/health` | 否 | — | `{ ok, mockMode, model, time }` |

约束：

- `prompt`：4-2000 字符；`lanes`：2-3；`instruction`：2-500；`variantId`：uuid。
- 所有项目级接口都同时校验 `project.userId === session.userId`，越权返回 404。
- 响应中的日期统一 `toISOString()`；服务端组件向客户端传的也是序列化后的视图对象。

### 5.3 赛马 SSE 协议

请求：`POST /api/projects/[id]/runs`，`Content-Type: application/json`。

响应头：

```text
Content-Type: text/event-stream; charset=utf-8
Cache-Control: no-cache, no-transform
Connection: keep-alive
X-Accel-Buffering: no
```

事件序列（正常）：

| 事件 | 数据 | 时机 |
| --- | --- | --- |
| `run_start` | `{ runId, source, personas[] }` | 创建 run 后立即 |
| `variant_done` | `{ variant, source, fallback? }` | 每路生成并入库后 |
| `variant_failed` | `{ idx, personaId, personaName, error }` | 单路失败 |
| `judge_start` | `{ count }` | 开始评分 |
| `judge_done` | `{ scores: [{ id, score, reasoning }] }` | 评分完成 |
| `run_done` | `{ runId, bestVariantId, versionId, source }` | 版本写入后 |
| `run_failed` | `{ runId, error }` | 全部失败且无法兜底 |

降级事件：

| 事件 | 数据 | 时机 |
| --- | --- | --- |
| `fallback` | `{ reason }` | 真实模型全部失败，切换内置示例 |

说明：

- 每个事件格式为 `event: <name>\ndata: <json>\n\n`。
- 客户端按 `\n\n` 分帧，允许任意网络分片；JSON 内部换行已被转义。
- 生成物 HTML 随 `variant_done` 一并下发，前端无需额外请求。
- `run_done` 后前端会再拉一次项目详情，以数据库为准同步版本列表。

### 5.4 错误约定

| 状态码 | 场景 |
| --- | --- |
| 400 | 参数校验失败、没有可迭代的基础版本 |
| 401 | 未登录 / 会话无效 |
| 404 | 项目或方案不存在、无权访问 |
| 500 | 创建 run 失败、服务端异常 |

## 6. 核心流程时序

### 6.1 首次赛马

```text
Browser                         Next Route Handler                 PostgreSQL / LLM
   │ POST /api/projects                 │                                  │
   │───────────────────────────────────▶│ insert project                   │
   │◀────────────── 201 { project } ────│                                  │
   │                                     │                                  │
   │ POST /projects/:id/runs (SSE)       │                                  │
   │────────────────────────────────────▶│ insert run(running)              │
   │◀─ run_start ────────────────────────│                                  │
   │                                     │ Promise.all(personas)            │
   │                                     │──── generate ───────────────────▶│
   │                                     │◀─── html ───────────────────────│
   │◀─ variant_done × N ─────────────────│ insert variant（逐路）           │
   │◀─ judge_start ──────────────────────│ judgeVariants ──────────────────▶│
   │◀─ judge_done ───────────────────────│ update score / selected          │
   │                                     │ insert version(v1)               │
   │◀─ run_done ─────────────────────────│ update run(done)                 │
   │                                     │                                  │
   │ GET /api/projects/:id               │                                  │
   │────────────────────────────────────▶│ select runs/variants/versions    │
   │◀──── { project, variants, versions }│                                  │
```

### 6.2 对话式迭代

```text
Browser: 当前 activeVersionId / activeVariantId + instruction
   │ POST /projects/:id/iterate
   ▼
Server:
   1. 校验项目归属
   2. baseVersion?.html ?? baseVariant?.html ?? pickActiveHtml(bundle)
   3. mock：在 HTML 中注入演示提示条
      live：把「当前 HTML + 修改要求」交给模型，输出完整新 HTML
   4. 写入 versions：vN，parent_version_id 指向 base
   5. 更新 project.updated_at
   ▼
Browser: 追加版本、切换到新版本、iframe 更新
```

### 6.3 手动选择方案

```text
Browser → POST /projects/:id/select { variantId }
Server:
  1. 校验 variant 属于该项目
  2. projects.selected_variant_id = variantId
  3. 若最新版本不是该 variant → 写入版本快照（保证预览取到正确内容）
Browser: 立即切换预览；若返回新版本则追加到版本列表
```

### 6.4 分享 / 导出 / 刷新恢复

- 分享：`/s/[id]` 服务端读取项目与版本，无需登录；取 `pickActiveHtml` 渲染只读 iframe。
- 导出：鉴权后返回 `pickActiveHtml`，`Content-Disposition: attachment`。
- 刷新恢复：`/p/[id]` 服务端加载 bundle，取最新 run 的 variants 与全部 versions；
  预览默认最新版本，赛马卡片显示分数与点评。

## 7. 关键实现细节

### 7.1 生成物：单文件 HTML

- 系统提示强制「只输出一个完整 HTML 文档」，CSS/JS 内联，无外部依赖。
- 模型输出后经 `extractHtml`：
  1. 去掉 Markdown 代码块标记；
  2. 从 `<!DOCTYPE>` 或 `<html>` 起截取；
  3. 截到最后一个 `</html>`；
  4. 校验存在 `<html>`、`<body>` 且长度 ≥ 200。
- 校验失败视为该路失败，不会把残缺代码送进 iframe。

### 7.2 提示词设计

- 生成系统规则（`src/lib/prompts.ts`）：中文界面、真实交互、localStorage 持久化、
  响应式、无外部图片/库、代码可直接运行。
- 三路人设：
  - 极简派：单屏、克制配色、只保留 1-2 个核心交互，≤250 行。
  - 功能派：增删改查、筛选、空状态、校验、持久化。
  - 视觉派：层次排版、渐变/玻璃拟态、过渡动画，但交互必须可用。
- 评审：需求匹配、交互完整性、视觉完成度、代码健壮性四维；每路 HTML 截取前 7000 字符；
  只输出 JSON；温度 0.1。
- 迭代：把「当前 HTML + 修改要求」一起给出，要求保留未要求改变的部分，输出完整文档。

### 7.3 并发与超时

- 三路 `Promise.all` 并行；每路独立 `try/catch`，失败只影响自己。
- 单次模型调用 120 秒超时（`AbortController` + `AbortSignal` 语义），可在 `LLM_TIMEOUT_MS` 调整。
- Route Handler `maxDuration = 300`，覆盖三路并行 + 评审的最坏情况。
- mock 模式人为延迟 `500 + index * 600` 毫秒，让逐路完成与进度 UI 可见。

### 7.4 评分与降级

```text
LLM 评审成功 ──▶ 使用评审分（0-100，夹紧）
      │失败
      ▼
规则评分 ──▶ 58 基础分
  + 8  存在 button/input/select/textarea/form
  + 6  存在 addEventListener / onclick
  + 5  使用 localStorage
  + 4  存在 @media
  + 5  HTML 长度 > 6000
  + 4  命中需求关键词组
  + 4  视觉派且存在渐变/动画特征
  最终夹紧到 45-96
```

评审失败不会让整个 run 失败；前端始终能拿到分数。

### 7.5 SSE 服务端与客户端

服务端：

- `ReadableStream` + `TextEncoder`，`send(event, data)` 统一编码。
- 客户端断开时 `controller.enqueue` 抛错 → 标记 `closed`，后续发送静默丢弃；
  数据库写入仍会完成。
- 所有异常路径都尝试把 run 置为 `failed` 并发送 `run_failed`。

客户端：

- `fetch` + `response.body.getReader()`，`TextDecoder(stream: true)` 处理跨分片 UTF-8。
- 缓冲区按 `\n\n` 切帧；每帧解析 `event:` / `data:` 行。
- 事件处理是 `async` 的（`run_done` 需要等待项目刷新），因此按顺序 `await`。

### 7.6 沙箱预览与 storage shim

- iframe `sandbox="allow-scripts allow-forms allow-modals allow-popups"`，**不加** `allow-same-origin`。
  生成代码处于不透明源：读不到宿主 Cookie、localStorage，也无法以同源身份调用业务接口。
- 代价：该源下浏览器禁止 localStorage。`preparePreviewHtml` 在 `<head>` 后注入探测脚本：
  - 原生可用 → 什么都不做；
  - 原生抛错 → `Object.defineProperty` 覆盖 `localStorage` / `sessionStorage`，用内存 Map 实现
    `getItem/setItem/removeItem/clear/key/length`。
- 预览内交互因此照常工作；导出为独立 HTML 后使用浏览器原生存储，刷新仍然保留。

### 7.7 会话安全

- 只存 `userId.signature`，不存用户信息；每次请求 `timingSafeEqual` 校验。
- `httpOnly` 防脚本读取；`sameSite=lax` 降低跨站请求风险；生产 `secure` 仅 HTTPS 发送。
- 密码体系被主动砍掉：昵称即身份，适合演示，不适合生产。

### 7.8 Next.js 16 适配

- Turbopack 同时用于 dev 与 build。
- `params`、`searchParams`、`cookies()` 均为异步：全部 `await`。
- Route Handler 默认不缓存；需要动态行为的路由显式 `export const dynamic = 'force-dynamic'`。
- create-next-app 默认开启 `cacheComponents`，与 Route Segment Config 冲突；
  本项目关闭该开关，保留传统动态渲染模型（详见问题记录）。
- 页面通过 `cookies()` 读取会话，天然动态渲染，不在构建期访问数据库。

### 7.9 前端状态机（Workspace）

核心状态：

| 状态 | 作用 |
| --- | --- |
| `variants` | 当前赛马的方案（含分数、点评） |
| `versions` | 版本时间线 |
| `activeVersionId` / `activeVariantId` | 当前预览对象，二选一 |
| `lanes` | 每路状态：idle/running/done/failed |
| `running` / `judging` | 赛马与评审进行中 |
| `runError` / `fallbackNotice` | 错误与降级提示 |
| `instruction` / `iterating` / `iterateError` | 迭代输入与状态 |
| `tab` | 预览 / 代码 |
| `copied` / `codeCopied` / `selectingId` | 交互反馈 |

派生预览：

```text
previewHtml =
  activeVersion?.html
  ?? activeVariant?.html
  ?? variants[0]?.html
  ?? null
```

自动赛马：仅当 URL 带 `autorun=1`、尚未启动、且初始没有方案时触发；
`runningRef` 与 `startedRef` 防止重复启动与 React 严格模式重复执行。

### 7.10 失败降级链

```text
无 LLM_API_KEY / LLM_MODE=mock
  → 直接使用内置示例（source=mock）

真实模型某一路失败
  → 该路 variant_failed，其余路继续

真实模型全部失败
  → 自动用内置示例补齐（fallback 事件，source=mock）
  → 仍按规则评分、选优、写版本，演示不中断

评审失败
  → 规则评分

模型输出不是完整 HTML
  → 该路失败；若全部如此，进入「全部失败」分支
```

演示能否跑完，不取决于额度、网络或 Key 是否可用。

## 11. 已知限制与演进

### 11.1 已知限制

- 昵称即身份，无密码、无邮箱验证；`SESSION_SECRET` 未配置时会退回内置开发密钥（生产必须配置）。
- 无速率限制、无内容审核；公开分享页凭 UUID 访问，不能撤销。
- 生成任务直接跑在 HTTP 请求中，没有队列；页面关闭后任务可能被中断。
- 迭代是单路生成，不是多路赛马；不能选中页面内元素做局部修改。
- 生成物 HTML 明文入库，无压缩与大小上限；没有为项目列表接口补索引。
- 生成代码虽被沙箱隔离，但仍可发起外部网络请求；未加 CSP。
- 无项目删除入口（API 已有 DELETE，UI 未暴露）。
- 未做 Safari/Firefox 兼容性验证。

### 11.2 后续优先级

1. **真实模型质量**：需求 → 结构化规格 → 代码两步走；附设计系统与组件样例，降低首轮失败率。
2. **迭代体验**：局部修改（元素级选择）替代整页重写；迭代也走多路对比。
3. **任务化**：队列 + 断线重连 + 失败重试，支持关页继续生成。
4. **可观测性**：记录每路耗时、token、失败原因，做质量面板。
5. **安全与治理**：速率限制、生成物 CSP、分享开关与过期时间、生产强制 `SESSION_SECRET`。
